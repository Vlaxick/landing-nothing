# Nothing — лабораторна робота №10

Варіант 2: BEM + ITCSS. Адаптивний лендінг на основі збірки лабораторної №9.

Макет: [v2 Nothing](https://www.figma.com/design/xIVUXiPZ3hdpEFiIC0qbTL/BOSE-New-Version?node-id=6802-139).

```sh
npm install
npm run dev
npm run build
npm run preview
npm run lint
npm run format
npm run images
```

## Архітектура стилів

Стилі організовано за ITCSS і підключено в `main.scss` від загального до конкретного:

```text
src/styles/
  1-settings/    токени та карти брейкпоінтів і сітки
  2-tools/       міксин mq() з перевіркою імені брейкпоінта
  3-generic/     скидання відступів і box-sizing
  4-elements/    базові стилі тегів і CSS custom properties
  5-objects/     структурні об'єкти o-container та o-grid
  6-components/  BEM-компоненти, кожен в окремому partial
  7-utilities/   допоміжні класи, зокрема u-visually-hidden
```

Порядок шарів — домовленість ITCSS: загальні правила йдуть перед конкретними, щоб каскад був передбачуваним. Це не нативні CSS `@layer`: звичайна специфічність та порядок правил у CSS продовжують діяти. Об'єкти мають префікс `o-`, компоненти — `c-`, утиліти — `u-`; елементи й модифікатори пишуться, наприклад, як `c-card__title` і `c-card--featured`. Блок не задає собі зовнішніх відступів: їх задає батьківський блок через BEM-мікс.

`Stylelint` перевіряє префікс відповідно до папки, BEM-іменування, забороняє ID та обмежує вкладеність трьома рівнями. У компонентах та об'єктах селектори тегів заборонені. `!important` дозволений лише в utilities. `mq('tablet')` і `mq('desktop')` створюють mobile-first медіазапити з токенів; некоректна назва спричиняє помилку Sass. Кожен компонент зберігається у своєму SCSS partial.

## Аналіз макета

У Figma перевірено планшетний фрейм шириною 744 px: заголовок hero — Space Grotesk Bold, 48 px, line-height 100%; текст About us — Space Mono Regular, 16 px, line-height 140%; колір обох — `#292929`. На мобільному заголовок hero має 36 px, на десктопі — 56 px. Ці значення занесено до SCSS-токенів; решту типографіки та відступів слід уточнити під час реалізації окремих блоків.

| Ширина фрейму | Колонки |   Поля | Gutter за підписом Info |
| ------------- | ------: | -----: | ----------------------: |
| 320 px        |       2 |  20 px |                   20 px |
| 744 px        |       6 |  72 px |          64 px (підпис) |
| 1260 px       |      12 | 120 px |                   24 px |

Підпис для планшета містить 64 px, але фактичні позиції в самому макеті вказують на 24 px: текст About us має ширину 288 px і починається на x=384 px; це рівно три колонки по 80 px із двома проміжками по 24 px, якщо поля дорівнюють 72 px. Тому для робочого токена вибрано 24 px. Підпис Figma зафіксовано як суперечність для звірки під час pixel-perfect перевірки.

## Модульна сітка

`o-container` центрує контент у рамці максимально 1260 px і задає внутрішні поля з токенів. Усередині `o-grid` використовує CSS Grid: 2, 6 або 12 рівних колонок і відповідний `column-gap`. Контентна область на 1260 px становить 1020 px. Між брейкпоінтами колонки еластичні; при ширині понад 1260 px контейнер центрується. Повноширинні hero та банер слід розміщувати поза контейнером.

Елемент `o-grid__item--full` займає всю сітку. Батьківські BEM-елементи секцій задають `grid-column` через мікси: фотографії галереї займають по одній колонці на мобільному, 4 + 2 на планшеті та 8 + 4 на десктопі. Для візуальної перевірки можна додати модифікатор `o-grid--debug` до сітки: він підсвітить колонки.

Геометрію перевірено в браузері на 320, 375, 744, 1000, 1260 та 1920 px: горизонтального переповнення немає, а на 1260 px елементи `span 8` і `span 4` мають ширину 672 і 324 px відповідно. Ключові координати звірено з Figma; повне накладання для pixel perfect — окреме завдання 5.

## Поведінка сторінки

Розмітка зібрана з Pug-макета, компонентів, масивів даних та міксина `picture`. Меню відкривається й закривається через CSS `:target`, без JavaScript. Під час відкриття решта сторінки приховується з фокуса; через відсутність JavaScript меню не перехоплює клавішу Escape і не переносить фокус автоматично. Кнопки й поля мають стани з макета та видимий клавіатурний фокус.

Контактна форма демонструє HTML-валідацію і не має сервера для надсилання повідомлень: після успішної перевірки браузер виконує GET на цю ж сторінку. Телефон і email відкривають відповідні застосунки через `tel:` і `mailto:`. Публікація та перевірки W3C і PageSpeed ще не виконані.

Декомпозиція BEM:

- `c-header` — логотип, телефон і перемикач меню; `c-menu` — навігація у відкритому меню.
- `c-hero` — головне зображення й заголовок; `c-section-title` — повторювані заголовки секцій.
- `c-product-card` — фото, назва, опис і ціна товару; `c-category` — пара фото та назва категорії.
- `c-button` і `c-field` — спільні кнопки та поля форми з модифікаторами за потреби.
- `c-about`, `c-contacts` і `c-footer` — змістові області сторінки.
- `o-container` та `o-grid` — структурні об'єкти контейнера і сітки. Зовнішні відступи компонентів задаються батьківськими елементами через BEM-мікси.

Додаткові виміряні токени: висота кнопки 56 px, поля 48 px, радіус обох 8 px; горизонтальні відступи кнопки 48 px, поля 16 px. Кнопка default `#292929`, pressed `#111111`, hover `#F8F8FA` з рамкою `#F0F1F4` завтовшки 2 px. Поле default має фон `#F8F8FA`; при hover рамка 1 px `#D5D7DE`, при focus — 1 px `#292929`. Підказка поля — Space Mono Regular, 14 px / 140%, `#7E7E83`. Змінні в `1-settings` і відповідні CSS custom properties у `4-elements` містять перевірені значення. Інші значення, що залежать від конкретної секції, слід звіряти при її верстці.

Фото hero, банера, карток і категорій завантажені з відповідних шарів Figma в `src/assets/images/`. Скрипт `npm run images` генерує AVIF, WebP та JPEG/PNG у двох ширинах без штучного збільшення. Оригінал банера має 1592 × 1269 px, тому 2× для повної ширини 1260 px недоступний з цього шару.

Макет містить окремі кадри hero для 320, 744 та 1260 px; усі три додані до проєкту для подальшого використання через `picture`.

Логотип та іконки експортовані з розділу Icons & Logo і оптимізовані SVGO. SVG логотипа, наданий Figma, містить вбудоване растрове зображення; він не є векторним контуром. Іконки використовують `currentColor`. Бургер містить три окремі лінії: в hover верхня має довжину 13 px, середня — 18 px, нижня — 9 px; стан можна зробити стилями на лініях при інлайн-підключенні SVG.
